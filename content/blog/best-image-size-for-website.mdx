Website images should look sharp on modern screens without slowing the page. The right size depends on where the image appears.

## Quick size recommendations

| Use case | Typical width | Practical file size |
| --- | --- | --- |
| Blog content image | 1200–1600px | 100–250KB |
| Product photo | 1000–1600px | 80–200KB |
| Hero / banner | 1600–2400px | 150–400KB |
| Thumbnail | 300–600px | 20–80KB |
| Logo | as needed | often under 50KB |

These are guidelines, not hard rules. Detailed photos need more data than flat graphics.

## Resize, then compress

Serving a 4000px photo inside an 800px column wastes bandwidth. Resize to the display size first, then compress.

CompressKit’s [Image Resizer](/image-resizer) helps with exact dimensions. After that, use the [Image Compressor](/compress-image) to reduce weight.

## Format choice for the web

- **Photos:** WebP or JPG
- **UI graphics / logos with transparency:** PNG or WebP
- **When compatibility is uncertain:** JPG for photos, PNG for graphics

## Performance checklist

1. Match dimensions to layout
2. Strip unnecessary metadata by re-exporting
3. Prefer WebP when your site supports it
4. Keep hero images optimized, not original camera files
5. Test on mobile data, not only Wi-Fi

Faster images mean faster pages — and better experiences for visitors on slower connections.
